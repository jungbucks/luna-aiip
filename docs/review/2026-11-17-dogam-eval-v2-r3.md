## 4. 회귀 정리 (요청 4번)

## 기준표 개선 제안

1. **접힘선을 "위쪽 끝"으로만 재면 한 뼘만 걸쳐도 통과한다.** 이번 폰 값 672px은 700px 선 안에 카드 위쪽 28px만 들인다. 학생이 실제로 누를 머리줄(제목)은 선 밖이다. "첫 카드 **제목 줄 아래 끝** ≤ 접힘선" 또는 "위쪽 끝 ≤ 접힘선 − 60px"처럼 머리줄이 들어오는 조건으로 바꾸길 제안한다(probe가 `.issue-title` bottom을 재면 된다).
2. **접이식 안에 든 범례는 H6인가 H10인가.** 2절 규칙 4의 예시는 "아예 없음 = H6 / 있지만 멂 = H10+P"뿐이다. 이번처럼 "이름은 배지 옆에 있고 뜻은 한 번 눌러야 보임"은 둘 다 아니다. 이번엔 H6 정의("배지의 뜻이 배지 가까이")에 따라 H6으로 셌다. "뜻이 접이식·마우스 올리기 뒤에 있음 = H6, 심각도는 이름만으로 뜻이 서는지로"를 예시로 추가하길 제안한다.
3. **보조 글자의 하한.** 프로젝트 기준 "본문 15px+"와 design.md 17~18px 사이에서, 배지·꼬리표·고지 같은 보조 글자(14~14.7px)를 언제 C 위반으로 볼지 정해져 있지 않다. r2는 가장 작은 13.6px만 셌다. "보조 글자 14px 이상은 통과, 미만은 C 1"처럼 숫자를 정하면 회차 사이 흔들림이 준다.
4. **새 기능의 "쓰기 쉬움"은 어느 원칙인가.** 🔗 링크처럼 기능은 맞는데 피드백·발견성이 약한 경우 H1(상태 가시성)과 H7(효율) 중 어디에 둘지 모호했다. 이번엔 대상이 교사용 지름길이라 H7로 두었다. "교사용 지름길 기능의 사용성 = H7"이라고 적어 두길 제안한다.
5. **토글 단추의 ARIA 판정.** H4 웹 표준 목록에 `aria-pressed`는 있지만, 이름이 바뀌는 토글에 `aria-pressed`를 겹쳐 쓰는 경우는 없다. "토글 = `aria-pressed`와 고정 이름 / 또는 이름 바꾸기만"을 H4 예시로 추가하길 제안한다.
