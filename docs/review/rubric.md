## 2. 점수 매기는 규칙 (모든 항목 공통 — 감으로 매기지 않는다)

1. 먼저 **위반 목록**을 만든다. 위반마다 `번호 · 원칙(H/E, CRAP 꼬리표) · 심각도 · 근거(파일:줄 또는 스크린샷) · 고칠 방법`을 적는다.
2. 심각도(닐슨 척도):
   - **1 겉치레** — 알아채도 이해·사용에 지장 없음
   - **2 경미** — 잠깐 멈칫하게 하거나 일부 학생이 헷갈림
   - **3 중대** — 많은 학생이 잘못 이해하거나 원하는 걸 못 함
   - **4 치명** — 페이지 목적(이해·탐색)을 막음
3. 항목 점수 = **10 − (가장 심한 위반의 감점) − (나머지 위반 1건당 1점, 최대 2점)**, 0 미만은 0.
   - 가장 심한 위반의 감점: 심각도 1 → 1 · 2 → 3 · 3 → 5 · 4 → 8
   - 위반이 없으면 10.
   - 심각도는 **영향 × 빈도**로 정한다(닐슨). 영향이 커도 겪는 학생이 드물면 한 단계 낮춘다(예: file://로 열면 빈 화면 — 배포는 웹 주소라 드묾 → 2).
   - 교육 축 예시: E2 첫 문장이 개념 정의로 시작 = 3, 구체 숫자가 학생 세계가 아닌 자료 개수뿐 = 1. E3 한 칸에 길이 규칙 위반 = 2, 번역투 한두 곳 = 1.
   - 2절 공식은 나머지 위반 감점이 최대 2점이라 위반 3건과 4건이 같은 점수가 될 수 있다(포화). 위반을 고쳤는데 점수가 그대로면 보고서에 "포화"라고 밝힌다.
4. 위반 하나가 두 원칙에 걸리면 **주된 원칙 한 곳에만** 센다(중복 감점 금지). 다른 원칙은 "관련"으로만 적는다.
   - 예: 배지 범례가 **아예 없음** = H6. 범례·고지가 **있지만 배지에서 멂** = H10(주) + P 꼬리표.
5. CRAP 점수는 위반 목록의 CRAP 꼬리표(C/R/A/P)만 모아 같은 규칙으로 계산한다. **꼬리표는 주된 원칙과 상관없이** 시각 성질이 있는 위반에 붙인다(예: 주된 원칙이 H10이어도 거리 문제면 P).
   - 글자 크기·행간(타이포 가독성)은 **C 대비**로 센다.
6. **문서끼리 부딪칠 때**: design.md와 프로젝트 설계서·교사 결정이 다르면 교사 결정을 따른다. 교사가 정한 것(아래 "교사 결정 목록")은 감점하지 않고 "정보"로만 적는다.

## 3. 사용성 — 닐슨 10원칙 (도감에 맞춘 정의)

| # | 원칙 | 이 도감에서 보는 것 | CRAP |
|---|---|---|---|
| H1 | 시스템 상태 가시성 | 지금 어떤 필터가 켜져 있고 몇 장이 보이는지, 카드가 펼쳐졌는지(▾), 배지가 사건 상태를 바로 알려 주는지 | — |

| H3 | 사용자 통제와 자유 | 펼친 것을 쉽게 접는지, 필터를 쉽게 푸는지, 게임으로 돌아가는 길, 뒤로 가기가 예상대로인지 | — |
| H4 | 일관성과 표준 | 같은 것은 같은 모양: 배지 하나에 뜻 하나, 양측 라벨 형식의 짝, 게임과 같은 권리 이모지·색, 링크·버튼 모양. 웹 표준(제목 태그, `aria-pressed`, `aria-live`, 이모지 `aria-hidden`) | **R 반복** |

| H7 | 유연성과 효율 | 주소로 카드 바로 열기(교사가 수업 중 공유), 모두 펼치기/접기, 키보드만으로 조작 | — |
| H8 | 미적이고 최소한의 디자인 | **C 대비**: 제목·배지·본문의 위계가 분명하고 장식(그라데이션 제목·큰 노란 숫자)이 내용과 눈길을 다투지 않는지, 글자 대비 4.5:1 이상. **A 정렬**: 보이지 않는 선 하나에 맞는지(design.md는 왼쪽 정렬 기준; 가운데·왼쪽 혼재). **P 근접**: 관련된 것은 붙고 다른 것은 떨어지는지(고지·범례와 배지의 거리, 출처와 사례). 정보 밀도(펼친 카드 길이) | **C · A · P** |
| H9 | 오류 인식·진단·회복 | 스크립트가 못 뜰 때(예: file://로 열면 빈 화면) 안내가 있는지, 필터 결과 0건, 깨진·막힌 링크 | — |
| H10 | 도움말과 문서 | 읽는 법(배지·카드 구조), 수업 활용 안내, 고지(법률 자문 아님·기준일)가 찾기 쉬운 곳에 있는지 | — |

CRAP 꼬리표 정리: **C 대비·A 정렬·P 근접 → H8**, **R 반복 → H4**. 위반을 적을 때 해당 꼬리표를 붙인다.

## 5. 측정 조건 (회차마다 같게)

- 대상: `dogam.html` + `css/dogam.css` + `js/dogam/*` + `data/issues.js`, 측정 시점의 커밋 해시를 적는다.
- 스크린샷 **4장 고정**(cwd = 프로젝트 루트, 래퍼 = scratchpad의 `shot-dogam.html`):
  1. 데스크톱 첫 화면: `--url="/__probe.html?w=1366&h=1250" --size=1366,1250`
  2. 폰 첫 화면: `--url="/__probe.html?w=390&h=1500" --size=500,1500`
  3. 폰 카드 펼침: `--url="/__probe.html?w=390&h=1600&open=tmmake&more=tmmake&scroll=tmmake" --size=500,1600`
  4. 데스크톱 카드 펼침: `--url="/__probe.html?w=1366&h=1250&open=train&more=train&scroll=train" --size=1366,1250`
- 링크 점검: node로 GET(브라우저 User-Agent, 리디렉트 따라감). 2xx = 살아 있음, 404·연결 실패 = 깨짐(H9 위반), **403 = 미확인**(봇 차단일 수 있어 감점하지 않고 적어만 둔다).
  - 명령: `node test/run-probe.mjs <래퍼 경로> --shot=<png> --url=... --size=...`. 브라우저는 한 번에 하나.
- 코드 측정은 node로(글자 크기·태그 수 등은 프로브나 계산값으로), `node test/verify-dogam.mjs` 결과를 적는다.
- 스크린샷으로 본 것과 코드로만 본 것을 구분해 적는다.

## 6. 보고서 형식

파일 `docs/review/<날짜>-dogam-eval-v2-r<회차>.md`:
1. 점수판 — 사용성(H1~H10), 교육(E1~E4), 종합, 보조 CRAP. 이전 회차가 같은 기준이면 나란히.
2. 위반 목록 표(번호·원칙·CRAP·심각도·근거·고칠 방법) — **점수는 이 표에서 2절 규칙으로만 계산한다.** 계산 과정도 한 줄씩 보인다.
3. 잘 된 점(유지할 것).
4. 다음 회차 우선순위: 점수가 가장 많이 오르는 수정 순서(글로 되는 것 / CSS 몇 줄 / 화면 기능 / 교사 결정 필요로 나눔).
5. 확인 방법 구분(스크린샷 / 코드·측정만).
