# AI 시대의 지식재산 쟁점 도감 — 설계 문서 (2026-07-18)

> luna-ip-game 자매 페이지(`dogam.html`). 게임이 지재권 6종 입문이라면, 도감은 그다음 — "AI 시대엔 이게 왜 어려운가"의 정답 없는 논쟁 12건.
> 브레인스토밍 확정: 둘 다 대상(학생 핵심 + 더보기 심화) · 양측 대립 카드 · 루나 자매 페이지 · **실제 최신 판례 리서치 기반, 미결은 "진행 중" 상태 표시**.

## 1. 목적·대상

- 대상: 루나 게임을 마친 고등학생(핵심) + 발표·논문 참고가 필요한 교사(더보기). 원천 = 사용자(교사) 논문의 쟁점 조사 12건.
- 단일 임무: 각 쟁점을 "한쪽 vs 반대쪽"의 살아있는 논쟁으로 보여주고, 실제 사례로 "지금 어디까지 왔는지"를 알려준다.
- 성공 기준: ① 훅 검문 통과 ② 카드 하나로 한 쟁점의 양측·현황 파악 ③ 미결 사건을 확정처럼 서술하지 않음(상태 배지 강제) ④ 사례·법리는 논문 저자(교사) 검수 통과.

## 2. 훅 (hook.md 준수)

- H1: **"AI가 만들었습니다. 그럼 누구 것이죠?"**
- 부제: "그림·발명·로고·알고리즘 — AI 시대가 던진 **12개의 논쟁**. 아직 법도 답을 정하지 못했습니다. 이번엔 당신이 판단할 차례."
- 장치: 미스터리/딜레마 + 구체 숫자 12. 첫 조작: 권리 필터 칩 또는 첫 카드 탭 → 즉시 양측 대립 펼침(3초).
- 약속: 12개 카드가 각 논쟁의 양측과 현재 사례를 끝까지 보여준다. 미결은 미결로 정직하게.

## 3. 콘텐츠 스키마

`data/issues.js` (★콘텐츠 전부, ES 모듈 export):

```
ISSUES = [{
  id, right: '저작권'|'특허권'|'상표권'|'영업비밀', rightEmoji,
  title,            // 쟁점 제목
  hook,             // 한 줄 도발 질문
  sides: [ { label, stance, points:[2~3] }, ... ],   // 2개(또는 #10은 3개)
  think,            // "생각해볼 질문"
  status: 'decided'|'ongoing'|'varies',  // ⚖️판결 / 🔥진행 중 / 🌍국가별·전략별 상이
  realCase: { name, gist, date },        // 실제 사례 요지
  sources: [ { label, url } ],           // 더보기 출처 링크
}]
STATUS_META = { decided:{emoji:'⚖️',label:'판결'}, ongoing:{emoji:'🔥',label:'논쟁 진행 중'}, varies:{emoji:'🌍',label:'국가·상황별 상이'} }
```

카드 렌더: `상태 배지 + 제목 → hook → 양측 대립(좌/우, #10은 3열) → 💭 생각해볼 질문 → [더보기] 실제 사례 요지 + 출처 링크`.
필터 칩: 전체 / 저작권(4) / 특허권(2) / 상표권(3) / 영업비밀(3).

## 4. 쟁점 12건 (리서치 기반 — 2026-07 조사)

각 항목 = 양측 대립 + 실제 사례 + 상태. **아래 사례 사실은 §8 검증표에서 교사 검수.**

**저작권 (4)**
1. **학습 데이터 무단 사용** — [도둑질: 창작자 동의·보상 필요] vs [공정이용: 인간처럼 보고 배움]. 사례: *Bartz v. Anthropic* — 학습 자체는 공정이용이나 해적 복제본 저장은 침해로 보아 약 15억 달러 합의(2025). *NYT v. OpenAI*는 산출물이 시장을 대체하는지로 진행 중. 상태: ongoing.
2. **AI 창작물의 저작권자** — [인간 저작 없으면 저작권 없음] vs [프롬프트·기획한 사람에게 인정]. 사례: *Thaler v. Perlmutter* — 美 대법원 상고 기각(2026-03), 순수 AI 생성물은 등록 불가, 인간 저작 요건 유지. 상태: decided.
3. **서비스 제공자의 책임** — [도구를 설계·학습시킨 회사 책임] vs [실제 지시한 이용자 책임]. 사례: *NYT v. OpenAI* — 산출물이 원저작물을 재현·경쟁하는지 다툼, 각하 신청 기각 후 진행 중. 상태: ongoing.
4. **오픈소스 라이선스 준수** — [라이선스는 계약, 반드시 준수·저작권 표시 유지] vs [학습·변형은 새 창작]. 사례: *Doe v. GitHub Copilot* — 저작권 표시(CMI) 제거(DMCA §1202) 쟁점으로 초점 이동, 항소·정지 중. 상태: ongoing.

**특허권 (2)**
5. **AI 기술 보호 방식** — [특허로 공개해 보호+기술발전] vs [공개하면 모방 쉬움, 영업비밀이 유리]. 전략 선택 논쟁(정답 없음). 상태: varies.
6. **AI 발명자 인정** — [발명자는 자연인만] vs [실제로 발명했으면 AI도]. 사례: *DABUS(Thaler)* — 일본 대법원(2026-03)·미국·영국은 AI 발명자 불인정, 독일은 "인간 발명자를 두되 AI 활용 발명은 특허 가능"으로 완화. 상태: varies(국가별 상이).

**상표권 (3)**
7. **AI가 만든 상표 등록** — [사용·식별력 있으면 창작 주체 무관 등록 가능] vs [인간 창작성 요건 문제]. 상태: ongoing.
8. **상표 침해·희석** — [유명 상표와 혼동·희석 유발 시 침해] vs [유사성·고의 입증 어려움]. 사례: *Getty v. Stability AI* — 산출 이미지에 왜곡된 Getty 워터마크. 美 법원은 희석 주장 유지(2026-04), 英 고등법원은 희석 기각(2025-11). 상태: varies(국가별 상이).
9. **AI 명칭 분쟁** — [선사용·등록 상표 보호] vs [분야 다르면 혼동 없음]. 사례: *Gemini Data v. Google* — 구글이 상표 소송에서 승소(2026-05). 상태: decided.

**영업비밀 (3)**
10. **핵심 기술 보호 방안(3택)** — [특허=공개하고 보호] vs [오픈소스=공유로 생태계] vs [영업비밀=비공개 독점]. 3열 대립. 상태: varies.
11. **설명 요구권 vs 영업비밀** — [개인의 알 권리: 왜 거절됐는지 설명받을 권리] vs [기업의 알고리즘 영업비밀]. 사례: *CJEU 판결(2025-02)* — 영업비밀만으로 설명 거부 불가하나 알고리즘 자체 공개는 불요, 예외적으로만 영업비밀 우선. 상태: varies.
12. **영업비밀 유출 예방** — [강한 계약·접근통제로 보호] vs [과한 통제는 인재 이동·혁신 저해]. 사례: *Apple v. OpenAI(2026-07)* — 전직 직원·채용 과정 통한 기밀 유출 주장, 진행 중. *xAI v. OpenAI*는 증거 부족으로 각하. 상태: ongoing.

## 5. 구조·기술

- `luna-ip-game/dogam.html` + `data/issues.js`(콘텐츠) + `js/dogam/main.js`·`js/dogam/render.js`(필터·카드·더보기 — 게임처럼 바닐라 ES 모듈, 빌드 없음) + `css/dogam.css`(게임 다크 네온 팔레트 변수 공유, 도감 카드 그리드).
- **게임 연결(양방향)**: `js/ui/ending.js` 엔딩 카드의 "🔄 처음부터 다시" 버튼 위에 티저 링크 1줄 — `<a href="dogam.html">🧭 법은 여기까지 배웠어요. AI 시대엔? → 쟁점 도감 열기</a>`. 도감 하단에 "← 게임으로 돌아가기"(index.html).
- 게임 코어(engine/state/main)는 **손대지 않음** — ending.js에 링크 1줄만 추가(수치·규칙 무변경, 기존 verify 23건 회귀 유지).

## 6. 디자인

- 게임의 다크 네온(퍼플~시안) 팔레트를 공유해 세계관을 잇되, 도감다운 정돈된 카드 그리드. 양측 대립은 좌우 색 대비(예: 시안 vs 마젠타), 상태 배지는 3색.
- 본문 15px+ (게임 규칙 상속), reduced-motion 존중. frontend-design 스킬로 최종 톤 확정.
