# ourlog — 팬 반응을 보는 가상 SNS 앱 (설계, 2026-11-20)

## 왜

몰입감을 높이려는 장치다. 무엇을 가르치려고 넣는 게 아니다. 학생이 "내 결정이 진짜 세상에 퍼진다"는 느낌을 받게 한다. 이 게임은 여러 면을 따져 보게 하는 게임이다. 그래서 같은 결정을 놓고도 팬들이 처음에 환호했다가 나중에 의심하는 장면이 그 목적에 맞는다(교사 말).

## 목표

- EP마다 결정이 끝나면 루나폰에 **ourlog** 알림이 온다. 알림 문구는 "ourlog SNS 앱을 확인해 보자!"다. 학생은 열어 볼지, 넘어갈지 고른다.
- ourlog를 열면 그 편 게시물 하나가 보인다. 그 아래로 댓글과 좋아요가 몇 초에 걸쳐 실시간처럼 올라온다.
- 팬 반응은 학생의 선택에 따라 다르다. 정답, 오답, 다시 선택해서 정답의 세 갈래다.
- 6편 동안 게시물이 쌓여 계정이 자라는 게 보인다. 📈 인지도가 좋아요와 팔로워 숫자로 보인다.

## 하지 않을 것

- 점수, 배지, 엔딩 판정에 영향을 주지 않는다. `engine.js`는 건드리지 않는다.
- 진짜 네트워크를 쓰지 않는다. 다른 학생의 반응도 받지 않는다. 댓글은 모두 미리 써 둔 글이다.
- 학생이 댓글을 쓰거나 좋아요를 누르는 기능은 없다. 게시물은 보기만 한다.
- 엔딩·산출물·리포트에 ourlog 내용을 넣지 않는다(이번 범위 밖).

## 실패로 칠 것 (기능이 돌아가도)

- **인스타그램 화면처럼 보이는 것.** 그라데이션 카메라 로고, 같은 모양의 하트·말풍선·공유 아이콘, 스토리 동그라미 고리를 쓰면 안 된다. 지재권을 가르치는 게임이다(SPEC §12.6 "특정 회사 UI를 본뜨지 않는다"와 같은 규칙). 배치(위 계정, 큰 사진, 아래 반응·댓글)는 SNS의 일반 문법이라 써도 된다.
- 수업 시간을 잡아먹는 것. 열어 보지 않으면 시간이 0초 더 들어야 한다. 열어도 EP당 15초 안에 다 볼 수 있어야 한다.
- 댓글이 혐오·욕설·조롱으로 흐르는 것. 비판 댓글도 "그 노래랑 후렴 진행이 비슷한데?"처럼 점잖게 쓴다.
- 실존 인물·브랜드·계정을 닮은 이름을 쓰는 것.

## 만드는 방법 (Approaches)

1. **루나폰의 네 번째 진짜 앱으로 만든다(선택).** 앱 층 `#appOurlog`, 모듈 `js/ui/ourlog.js`, 데이터 `data/ourlog.js`로 나눈다. 진행 흐름에는 `main.js`가 한 단계를 끼운다. 메신저·권리 수첩·설정과 같은 틀(`phone.js`의 `LAYER`·`DOCK`, 뒤로 가기 규칙, inert)을 그대로 쓴다.
2. 메신저 채팅 부품을 다시 써서 댓글을 말풍선으로 흘린다. 코드는 적지만 SNS처럼 보이지 않는다. 대화 규칙(말투 검사, 이어 말하기 생략)과도 얽힌다. → 버림.
3. 따로 `ourlog.html` 페이지를 만든다. 폰 한 대라는 환상이 깨지고, 저장 상태를 다시 읽어야 한다. → 버림.

1만 이 프로젝트의 구조(게임 전체가 폰 한 대, 앱 층, 데이터와 화면 분리)에 맞는다.

## 설계

### 1. 흐름

```
선택 → 결과 → O/X → 수첩 적기 → [ourlog 알림] → 정산 → 다음 EP
                                  ├ 열기 → ourlog 앱(그 편 게시물, 실시간 반응) → ‹ 닫으면 정산
                                  └ 넘어가기 → 정산
```

- 알림 카드는 `#homeScreen` 밖, `#app`의 자손으로 둔다(알림이 뜰 때는 메신저가 열려 있어 홈 화면이 inert다 — 만드는 사람의 결정).
- 알림은 폰 위쪽에서 내려오는 카드다. 기존 `#notifBanner`와 같은 문법이고, 단추 두 개 [ourlog 열기] [넘어가기]가 있다. 떠 있는 동안 뒤 화면은 팝업처럼 inert다. 키보드 초점은 [ourlog 열기]에 간다. ESC는 [넘어가기]다.
- **최종 법정으로 끝나는 EP에는 알림이 없다**(퀴즈가 없는 것과 같은 규칙). 집행유예 EP는 평소대로 뜬다.
- ourlog를 닫으면 정산(`bridge`)으로 이어진다. 열어 둔 채로는 정산이 오지 않는다. 학생이 닫아야 한다.
- 평소에는 홈의 ourlog 아이콘으로 언제든 연다(눌리는 때는 다른 독·홈 앱과 같은 규칙 — 스토리 중·앱이 열려 있을 때·답장을 기다리는 동안은 안 눌림. 만드는 사람의 결정). 이때는 지금까지 쌓인 게시물이 다 보인다. 실시간 연출 없이 댓글이 모두 나온 상태다. 아이콘 자리는 장식 앱 '윤리시티'다(div → 진짜 단추로 바꾼다). 스토리가 흐르는 동안과 앱이 열려 있는 동안에는 안 눌리는 다른 앱과 같은 규칙을 따른다.

### 2. 어느 반응이 나오나 — 저장을 늘리지 않는다

게시물의 갈래는 그 EP 배지에서 바로 나온다. **새 저장 칸이 필요 없다.**

| 배지 `G.badges[i]` | 갈래 | 반응 |
|---|---|---|
| `'full'` | `right` | 응원 위주. 정답의 대가(늦어짐 등)를 아쉬워하는 댓글이 한둘 섞일 수 있다 |
| `'half'` | `half` | `right` 댓글에 "처음엔 좀 불안했는데" 류 1~2줄을 섞는다 |
| `'none'` | `wrong` | 처음엔 환호하다가 뒤로 갈수록 의심·역풍이 섞인다. 그 편 오답 결과(내용증명, 짝퉁, 팬 항의 등)와 맞는다 |
| `null` | — | 아직 선택 전이라 게시물이 없다 |

이어 하기는 EP 시작 사본으로 돌아간다. 그래서 진행 중인 편의 게시물은 사라졌다가 다시 고르면 다시 생긴다. 의도한 동작이다.

### 3. 데이터 `data/ourlog.js`

```js
export const OURLOG = {
  account: { handle: '{N}_official', bio: '...' },   // 이름 토큰 사용, 하드코딩 금지
  posts: {
    1: {
      img: { right: 'ep1', wrong: 'ep1' },            // assets/ourlog/<idol>/<key>.webp
      caption: { right: '...', wrong: '...' },        // half는 right를 쓴다
      comments: {
        right: [{ who: 'moon_1004', text: '...' }, ...],   // 8~10개, 나오는 순서대로
        wrong: [...],                                       // 앞쪽은 환호, 뒤쪽은 의심
        half:  [...],                                       // right에 끼워 넣을 1~2개(위치 포함). 끼워 넣은 뒤 8~10개
      },
      likes: {                                        // 좋아요 배율
        live: { right: 1.0, half: 0.9, wrong: 1.3 },  // 알림으로 막 열었을 때 — 오답이 더 터진다
        later: { right: 1.0, half: 0.9, wrong: 0.6 }, // 지난 게시물로 다시 볼 때 — 역풍이 반영돼 정답보다 적다
      },
    },
    // 2~6
  },
};
```

- 글쓴이 이름은 지어낸 영문 소문자 아이디다. 실존 인물·브랜드·실제 계정 형식(공식 인증 표시 등)은 쓰지 않는다. 한 편 안에서는 같은 아이디가 겹치지 않게 한다.
- 댓글은 40자 이하다. 이모지와 ㅋㅋ는 써도 되지만, 기존 금지 유행어(verify `SLANG`)와 욕설·조롱은 안 된다.
- 문구는 교사 검수 대기로 표시한다.

### 4. 화면 `#appOurlog` (앱 층, `#app`의 자손)

위에서 아래로:

1. 머리줄: ‹ 뒤로, `ourlog` 글자 로고(악센트 색, 그라데이션 아이콘 없음), 실시간 재생 중일 때만 LIVE 점.
2. 계정 줄: 아이돌 프로필(기존 캐릭터 PNG 동그랗게), `{N}_official`, 팔로워 수.
3. 게시물(최신 편이 맨 위): 계정·"방금", 큰 그림(정사각형, 둥근 모서리), 반응 줄(좋아요 숫자, 댓글 수), 글(caption), 댓글 목록.
4. 아래로 지난 편 게시물이 같은 모양으로 이어진다.

실시간 연출(알림으로 연 그 편 게시물만):

- 댓글이 약 0.7초마다 하나씩 아래에 붙는다. 좋아요 숫자는 그동안 목표 값까지 올라간다. 그림 오른쪽 아래에서 하트가 떠오른다.
- 화면을 누르면 남은 댓글이 한 번에 다 나온다(채팅의 "빨리 감기"와 같은 문법). 다 나오면 LIVE 점이 꺼진다.
- `prefers-reduced-motion`이면 처음부터 다 나온 상태로 보인다(하트·카운트업 없음).
- 헤드리스 검사는 움직임 줄이기가 강제라 끝 상태로 확인한다(CLAUDE.md 함정 참고).

숫자:

- 팔로워 = 지금 📈를 바탕으로 한 값(예: 📈 20 → 1.2만, 📈 95 → 8만대). 정확한 식은 만드는 사람이 정한다. 다만 📈가 오르면 늘고 내리면 준다.
- 게시물 좋아요 = 지금 📈 × 갈래 배율. 실시간 연출 중인 그 편 게시물은 `likes.live`, 그 밖(홈 아이콘으로 열었을 때, 지난 게시물)은 `likes.later`를 쓴다. 그래서 같은 오답 게시물도 막 올렸을 땐 크게 터지고, 나중에 다시 보면 줄어 있다(교사 결정). verify는 6편 모두 `live.wrong > live.right`이고 `later.wrong < later.right`인지 본다.
- 화면에 넣는 숫자는 반드시 정수로 만들어 글자로 넣는다(보안 검토 C — `num()` 같은 통로).

모양:

- 다크·라이트 두 모드를 모두 지원한다. 앱 바탕은 메신저처럼 불투명한 `--app-bg`이고, 흐림 효과는 쓰지 않는다(스크롤되는 면).
- 반응 아이콘은 직접 그린 선 아이콘이다. 하트는 둥근 하트가 아니라 이 게임의 별·달 같은 독자 모양도 괜찮다. 만드는 사람의 판단에 맡기되 인스타 아이콘을 닮지 않게 한다.

### 5. 그림 (codex 의뢰)

- 경로: `assets/ourlog/sol/*.webp`, `assets/ourlog/luna/*.webp`. 정사각형 1080px 이하, 장당 150KB 이하, 합계 2.5MB 이하. `assets/`는 이미 배포 범위다.
- 장수: 기본은 **EP마다 1장 × 솔·루나 = 12장**이다. 결정에 따라 장면 자체가 달라지는 편은 갈래별 2장으로 둔다.
  - EP5: 팬 얼굴이 그대로 / 얼굴을 가림
  - EP6: 배우 K 닮은 광고 / 아이돌 그대로
  - 그래서 **합계 16장**이다(8장 × 2명).
- 그림이 오기 전과 불러오기에 실패했을 때는 그라데이션 바탕에 그 편 권리 이모지를 보여 준다. 기능은 그림 없이 먼저 끝낼 수 있다.
- 그림 의뢰서(편별 장면 설명, 금지 사항 — 실존 인물·로고·인스타 화면 요소)는 구현 계획에서 쓴다.

### 6. 접근성

- 알림과 앱 모두 키보드만으로 끝까지 갈 수 있다. 알림이 뜨면 [ourlog 열기]에 초점이 간다. 앱을 열면 ‹에 초점이 가고, 닫으면 다음 단계의 초점 규칙(정산 팝업)을 따른다.
- 댓글 목록에 aria-live는 걸지 않는다(시끄럽다). 다 나온 뒤 목록으로 읽힌다.
- 떠오르는 하트, 장식 아이콘은 `aria-hidden`이다.

### 7. 검증 (기존 틀에 더한다)

- `verify.mjs`
  - OURLOG 6편 × 갈래 3개가 다 있는지
  - 댓글 수 8~10(half는 끼워 넣은 뒤), 길이 40자 이하
  - 좋아요 배율: `live.wrong > live.right`, `later.wrong < later.right`
  - 금지 유행어, 이름 하드코딩 없음
  - 편 안 아이디 중복 없음
  - 배지 → 갈래 매핑
- `probe.html`
  - 수첩 적기 뒤 ourlog 알림이 뜨는지
  - [넘어가기]로 정산이 오는지
  - [열기]로 그 편 게시물·갈래에 맞는 댓글이 나오고, 닫으면 정산이 오는지
  - 화면을 누르면 댓글이 다 나오는지
  - 최종 법정 EP에는 알림이 없는지
  - 홈 아이콘으로 지난 게시물이 보이는지
  - 이어 하기 뒤 게시물이 배지와 맞는지
  - 다크·라이트 대비 4.5:1
  - 상태바가 겹치지 않는지
- 6편 완주 프로브(임시)에 ourlog 열기·넘어가기 경로를 섞어 엔딩까지 가는지 본다.
- 캡처: 알림, 오답 게시물, 정답 게시물, 지난 게시물 목록. 1280×680과 390×844에서, 다크와 라이트로 찍는다.
