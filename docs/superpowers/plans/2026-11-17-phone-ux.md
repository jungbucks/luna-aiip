# 루나폰(v0.6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 게임 전체를 폰 한 대(잠금화면 → 홈 → 메신저 앱)로 바꾸고, EP마다 알게 된 것을 권리 수첩에 적어 마지막에 산출물 한 장으로 내보낸다.

**Architecture:** 지금 화면 뼈대와 id는 그대로 두고 `#app`을 폰 화면으로 감싼다. `#scr-ep` 안에 홈 화면과 앱 층 세 개(메신저=`#phoneWrap`, 권리 수첩, 설정)를 얹고, `main.js`의 진행은 "스토리 끝 → 알림 대기 → 누르면 채팅"과 "퀴즈 뒤 → 적기 → 정산" 두 군데만 바뀐다. 규칙(`engine.js`)·퀴즈·이어 하기·게임 저장은 손대지 않는다.

**Tech Stack:** 바닐라 HTML/CSS/ES 모듈, 빌드 없음, 외부 CDN 없음. 검산은 Node(`test/verify.mjs`), E2E는 헤드리스 Edge 프로브(`test/probe.html`).

**Spec:** `docs/superpowers/specs/2026-11-17-phone-ux-design.md` — 반드시 함께 읽는다. 눈으로 볼 기준은 같은 폴더의 시안 두 장(`…-mockup-home-messenger.html`이 최종, `…-mockup-screens.html`은 잠금화면·스토리 카드·알림창만 참고). 색·여백 값은 시안의 CSS가 출발점이다.

## Global Constraints

- 작업 브랜치 `v0.6-phone-ux`(main에서 분기). 커밋은 로컬에만, **push 금지**(사용자가 말할 때만).
- **수정 금지 파일**: `js/engine.js`, `js/quiz.js`, `js/resume.js`, `js/state.js`, `data/episodes.js`, `data/quiz.js`, `dogam.html`, `css/dogam.css`, `js/dogam/*`.
- `node test/verify.mjs`의 기존 42건과 `node test/verify-dogam.mjs` 10건은 매 태스크 끝에 그대로 통과해야 한다.
- 스펙 §3의 화면 요소 약속(id·클래스)을 전부 유지한다.
- 본문 글자 15px 이상, 라벨 12.5px 이상, 글 입력칸 16px 이상.
- 화면에 "루나"·"솔"을 직접 쓰지 않는다(`{n}` 토큰 + `T()`/`esc()`). 새 UI 문구는 `data/strings.js`의 `ui`에만 둔다.
- 학생이 적은 글을 화면에 넣을 때는 항상 `esc()`를 거친다(`innerHTML`에 날것 금지).
- 흐림(`backdrop-filter`)은 배경화면 위에 떠 있고 스크롤되지 않는 면에만. 메신저 앱 안과 스크롤되는 목록에는 쓰지 않는다. `@supports not (backdrop-filter: blur(1px))`와 `@media (prefers-reduced-transparency: reduce)`에서는 유리 면을 불투명도 0.92 이상으로.
- 움직임은 `transform`·`opacity`만, `@media (prefers-reduced-motion: reduce)`에서 전부 끈다.
- 그라데이션 글자, 카드 왼쪽 색 띠, 다이내믹 아일랜드 모양, 눌러도 반응 없는 버튼 금지.
- 팝업이 떠 있는 동안 `#app`의 `#popup` 아닌 자식은 전부 `inert`(지금 `popup.js` 동작). 새 층은 `#app`의 자식이거나 그 자손이어야 한다.
- 기준 화면: 기기 틀 390×600(안쪽)에서 잠금화면·홈·메신저(선택지 3개)가 잘리지 않는다. 전체 화면 모드 375px에서 가로 스크롤 0.

## Review Focus

테스트가 없으면 놓치기 쉬운 것 다섯 가지 — 각 줄의 테스트는 괄호 안 태스크에 들어 있다.

1. **낮은 화면에서 선택지 3개 + 긴 문구** → 입력창과 세 버튼이 모두 화면 안에 있고 대화 영역이 줄어들며 스크롤된다(Task 3, 프로브 `low-height`).
2. **알림·선택지 연타** → 채팅이 두 번 시작되지 않고, 선택이 한 번만 적용된다(Task 2 `notify-double`, Task 3 `pick-double`).
3. **팝업이 떠 있을 때·적기 단계에서 뒤로 가기** → 팝업도 앱도 그대로다(Task 2 `back-during-popup`, Task 5 `back-during-note`).
4. **저장소를 못 쓰는 브라우저(시크릿 등)** → 적은 글이 저장되지 않아도 게임이 멈추지 않고 그 판에서는 글이 보인다(Task 5, verify `notes-storage-throws`).
5. **자판이 올라온 좁은 높이에서 적기** → 글 상자와 [수첩에 적기]가 스크롤로 닿는다(Task 5, 프로브 `note-short`).

- [ ] **Step 6: `js/ui/theme.js` 구현**

위 Interfaces의 여섯 가지를 내보낸다. `resolveTheme`: `pref`가 `'light'`·`'dark'`면 그 값, 아니면 `systemDark ? 'dark' : 'light'`. `setThemePref('system')`은 키를 지운다. `applyTheme()`은 `document.documentElement.dataset.theme`과 `meta[name=theme-color]`(다크 `#0b0e22`, 라이트 `#eef0fb`)를 맞추고, `#btnTheme`의 `aria-label`을 `STRINGS.ui.themeToDark/Light`로 바꾼다. `toggleTheme()`은 지금 보이는 모드의 반대를 명시 저장한다. 저장이 `'system'`인 동안 `matchMedia('(prefers-color-scheme: dark)')`의 `change`에 `applyTheme`. `localStorage` 접근은 전부 try/catch.

`index.html` `<head>`의 스타일시트 링크 **앞**에 모듈이 아닌 인라인 스크립트(첫 화면 번쩍임 방지):

```html
<script>(function(){var p;try{p=localStorage.getItem('luna_theme')}catch(e){}
if(p!=='light'&&p!=='dark')p=matchMedia('(prefers-color-scheme: dark)').matches?'dark':'light';
document.documentElement.dataset.theme=p;})();</script>
```
